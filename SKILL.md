# Dataset Builder

Transform any collection of raw files (PDFs, Markdown notes, text documents, technical manuals, audio research, or code documentation) into a production-grade, dual-access database.

The resulting dataset is engineered specifically for **dual-ecosystem compatibility**:
1. **Producer Pal the APP (`Live Actions Helper / Genius`)**: Discovers topics line-by-line via `library_search` on `INDEX.md`, reads modular markdown chapters (<15,000 chars) via `library_read`, and executes direct Live Actions parameter blueprints.
2. **AI Skills & Data Tools (`producer-pal-genius`, `ai-database-browser`, Claude, Grok, Antigravity)**: Performs instant BM25 ranked full-text queries via SQLite FTS5 (`search.py`) and analyzes datasets via Apache Parquet.

## MANDATORY RULE: Destination Must Be Specified First

> [!IMPORTANT]
> **Never start building into a default or assumed location without confirming the destination directory first.**
> 
> If the user asks to turn a source folder into a dataset but does NOT explicitly name the destination directory:
> 1. **STOP immediately.**
> 2. Ask the user: *"Where should the dataset be created? (e.g., `B:\DATABASES\Music_Audio\<DatasetName>`)"*
> 3. Only proceed with scanning and compilation once the destination path is confirmed.

## Standard Dataset Deliverables

Every generated dataset directory contains:
```text
<DatasetName>/
├── markdown/                     <-- Categorized, modular markdown files (<15k chars each)
│   ├── <category_1>/
│   │   ├── doc_001.md
│   │   └── doc_002.md
│   └── <category_2>/
├── <dataset>.db                  <-- SQLite FTS5 database (documents, chunks, categories, chunks_fts)
├── <dataset>.parquet             <-- Apache Parquet columnar archive (Snappy compressed)
├── <dataset>_chunks.jsonl        <-- Semantic ~500-word chunks with metadata and tags
├── <dataset>_docs.jsonl          <-- Document-level catalog and word counts
├── search.py                     <-- Interactive standalone BM25 full-text search CLI
├── INDEX.md                      <-- High-density Producer Pal App router table + Live Actions blueprints
├── SCHEMA.md                     <-- Comprehensive SQL and JSON schema documentation
└── README.md                     <-- Dataset overview, statistics, and dual-access usage guide
```

## Step-by-Step Workflow

### Step 1: Validate Inputs & Destination
Ensure both the source path and destination path are known and verified.
- Source path: Path containing raw documents (`.pdf`, `.md`, `.txt`, `.json`, etc.).
- Destination path: Target folder for the dataset (e.g. `B:\DATABASES\Music_Audio\<DatasetName>`).

### Step 2: Run the Bundled Builder Engine
Execute the automated engine from the skill's `scripts/` folder:

```bash
python "C:\Users\<you>\.agents\skills\dataset-builder\scripts\build_dataset.py" \
  --source "B:\Documents\TRAINING DOCS\TargetFolder" \
  --dest "B:\DATABASES\Music_Audio\MyDataset" \
  --name "MyDataset" \
  --domain "music"
```

Available CLI Flags:
- `--source <path>`: Source directory containing raw documents/PDFs (for full build).
- `--add <path>`: Incremental addition source directory (appends new files into an existing dataset without overwriting previous contents).
- `--dest <path>`: (Required) Destination directory.
- `--name <name>`: Custom dataset name (defaults to destination folder name).
- `--description <text>`: Custom overview description.
- `--domain <music|general>`: Presets the Live Actions capability matrix and action blueprints in `INDEX.md`.
- `--chunk-words <int>`: Words per chunk (default: 500).
- `--chunk-overlap <int>`: Overlap words between chunks (default: 50).

### Step 3: Verify Dataset Output
Run automated verification on the newly created dataset:
1. Verify `INDEX.md` exists and all referenced markdown files exist under `markdown/`.
2. Test the SQLite FTS5 search engine:
   ```bash
   python "<dest>\search.py" "<keyword>" --limit 3
   ```
3. Check Parquet and JSONL file sizes.

### Step 4: Update Studio Registries (If on Drive B)
If the dataset was created inside `B:\DATABASES\`:
1. **Master Index**: Add the child index row to `B:\DATABASES\Music_Audio\INDEX.md`.
2. **AI Database Browser**: Ensure the new database is tracked by running `ai-database-browser` `--health`.

## Live Actions / Producer Pal Capability Schema in `INDEX.md`

Every `INDEX.md` generated by this skill must include:
1. **Header & Metadata**: Document count, word count, category breakdown.
2. **How Producer Pal Reads This**: Protocol for `library_search` and `library_read`.
3. **Capability Matrix**: Explicit checkboxes for what Live Actions / Pal can do natively (Native devices, track routing, MIDI clips) vs cited handoffs (third-party VST/AU knobs, stem separation).
4. **Action Blueprints**: Real, runnable Python tool call blocks (`live_create_device`, `live_update_device`, `live_write_notes`).
5. **Decide First Quick Table**: High-density keyword lookup table.
6. **Complete Document Catalog**: Tables of every document organized by category.
